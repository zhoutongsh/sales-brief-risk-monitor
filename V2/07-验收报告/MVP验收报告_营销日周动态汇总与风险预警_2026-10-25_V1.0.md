# 营销日周动态汇总与风险预警 MVP V0.1 验收报告

- 报告编号：MVP-ACC-2026-10-25-01
- 版本：V1.0
- 验收日期：2026-10-25
- 验收对象：营销日周动态汇总与风险预警 MVP V0.1（PC Web + FastAPI + SQLite）
- 报告性质：在既有独立测试、独立验收和 1000 条专项测试基础上做汇总复核，并补跑全量自动化回归；不替代独立验收方的原始报告

> **验收结论：通过（MVP 演示/试点范围）。同意内部演示和试点准备，不同意生产上线。**
>
> 一句话：核心闭环已经跑通，数据、权限、风险、导出和 1000 条线索专项都有证据；但定时调度、真实数据源、真实推送、12 条规则和生产安全还没有完成，不能把“演示通过”当成“生产就绪”。

## 一、结论先说

| 问题 | 结论 |
|---|---|
| 本轮验收是否通过 | **通过**，限定为 MVP 演示/试点范围 |
| 两个必保功能 | 日/周简报、风险识别与闭环均通过；风险范围按用户确认的 6 类交付 |
| 有没有阻断问题 | 没有。P0=0、P1=0、P2=0 |
| 还有哪些改进项 | 4 个 P3：无定时器、组织级投入产出比分母口径、失败横幅挤首屏、坏数据提示太笼统 |
| 能不能上生产 | **不能**。真实 CRM/ERP、真实推送、定时调度、12 条规则、生产安全、并发和留存均未验证 |
| 本次补跑结果 | 全量独立回归 **102/102 通过**，52.49 秒；演示库哈希前后一致，未被修改 |

### 1.1 为什么可以放行

- **主流程完整**：取数 → 12 项指标 → 6 类风险 → 日报/周报 → 认领/转派/关闭 → 审计，能从头走到尾。
- **数据算得对**：演示日 48/48、10 个工作日 480/480 与源数据独立复算一致；金额误差 0 元，比率误差 0 个百分点。
- **风险找得准**：10 条预期风险 10/10 命中，类别、级别、对象、负责人、金额全部一致。
- **权限和脱敏过关**：37 项 + 15 项权限检查通过；未登录 401、越权 403；手机号、邮箱在页面、接口、Excel、打印页均打码。
- **1000 条数据过关**：1,000 行逐字段入库，30 天日计数一致，质量 100 分；专项 18/18，全量 102/102。

### 1.2 为什么不能上生产

- 没有定时调度器，当前靠人工触发；“08:30 发布”是计划时间，不是实际自动生成时间。
- 数据来自 10 个 CSV，未接真实 CRM/ERP；没有真实钉钉、企微、邮件推送，只有站内通知。
- 风险规则为 6 类、8 个独立触发条件，不是 PRD 原文的“至少 12 条规则”。
- 演示登录无密码、HTTP Cookie、无 CSRF、导出二次确认只在前端、Excel 公式注入未修；不能放公网。
- 没做 50 并发压测、12 个月留存、真实数据试点，不能回答生产环境的性能和效果问题。

## 六、缺陷与改进项

| 编号 | 级别 | 问题 | 影响 | 处理建议 |
|---|---|---|---|---|
| P3-01 | P3 | 没有定时调度器；“08:00 前完成”未验证；发布时间是计划时间 | 上试点后不能保证每天自动出报 | 试点前加 Windows 计划任务或调度器，并证明 08:00 前跑完 |
| P3-02 | P3 | 组织级营销投入产出比的分母是公司级费用 | 组织之间横向比较可能失真 | 按组织拆分市场费用，或在页面显著标注不可比 |
| P3-03 | P3 | 批次失败横幅在 1280×720/800 下把风险第三条挤出首屏 | 只在失败、显示旧数据时出现；正常日报不受影响 | 横幅可折叠或压缩上方间距 |
| O-01 | P3 | 坏数据失败时只提示“源数据校验失败”，不显示行号/字段/原因 | 业务人员不知道哪一行错，修数据要靠开发查日志 | 试点前补“文件名 + 行号 + 字段 + 原因”，最多展示前 100 条 |

> 计数：P0=0、P1=0、P2=0；验收基线 3 个 P3，1000 条专项新增 1 个 P3，共 4 个改进项。都不阻断内部演示，但 P3-01 和 O-01 建议在试点前解决。
